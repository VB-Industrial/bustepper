# bustepper — минимальный стенд TMC5160

STM32G474, SPI1, Cyphal/CAN FD 1/8 Мбит/с, узел **42**. Управление через
Yakut на Raspberry Pi. Без VBBoot, энкодера, EEPROM, калибровки и ограничений
хода. Образ начинается с `0x08000000`.

## Сборка

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
./scripts/test.sh
```

Результаты: `build/bustepper.elf`, `.hex`, `.bin`. Прошивка отдельной явной
командой `./scripts/flash.sh`; она записывает Flash и перезапускает MCU.
Если подключено несколько ST-Link, задайте `STLINK_USB_LOCATION` (USB topology
из `lsusb -t`), чтобы OpenOCD выбирал нужный адаптер. Серийные номера обнаруженных
адаптеров совпадают. OpenOCD при прошивке определил 128 КиБ Flash; linker ограничен этим объёмом.

## Аппаратура и заменяемая библиотека

- Основа: `/home/robot/projects/STM32_TMC5160_SPI`: GPIO, SPI mode 3,
  startup, тактирование HSE 8 МГц → SYSCLK 160 МГц, библиотека `tmc5160.h`.
- Из РУКИ: текущие `fdcan.c/.h`, HAL и `libcxxcanard`, схема Register Access/List,
  GetInfo и Heartbeat. FDCAN1 RX **PB8**, TX **PB9**; SPI1 CS **PA4**,
  SCK/MISO/MOSI **PA5/PA6/PA7**, ENN **PC5**, SPI_MODE **PA11**, SD_MODE **PA12**.
- `Core/Inc/robot_config.h`: мотор, микрошаги, редуктор, частота TMC,
  параметры chopper/ramp и начальные значения тока.
- `Core/Inc/tmc5160.h` скопирован **без изменений**. Обновлённый заголовок
  заменяется здесь; при изменении API потребуется адаптация `bench.cpp`.
- Адаптер масштабирует радианы для редуктора, изменяемого во время работы,
  и вызывает высокоуровневые `set_pos`, `move`, `set_velocity`, `set_acceleration`.
  Команда в шагах вызывает регистровый API позиционирования.
- Адаптер блокирует включение ENN при `init()`: текущий заголовок сам включает
  драйвер. Разрешение — только через `arm 1`. SPI HAL вызовы ограничены 20 мс;
  ошибка выключает ENN, учитывается в `status`, требует повторного `arm 1`.
  При включении проверяется версия TMC5160 в IOIN (`0x30`).

## Регистры

Все настройки в RAM, `persistent=false`: после перезапуска действуют значения
из `robot_config.h`. IHOLD/IRUN применяются сразу через `set_current()` с
сохранением второго тока и задержки, без вызова `init()`.

**Шаг = микрошаг TMC** при разрешении из `robot_config.h` (сейчас 256 микрошагов
на полный шаг, 200 полных шагов на оборот двигателя). Радианы, рад/с и рад/с²
относятся к выходу редуктора. `gear_ratio` = обороты двигателя / оборот выхода.
Позиции абсолютные относительно счётчика XACTUAL; это расчётное положение TMC,
а не измеренное положение вала. Пропущенные шаги без внешнего датчика не видны.

| Регистр | Назначение |
|---|---|
| `arm` | 0 выключить силовую часть, 1 включить; при включении мотор должен стоять |
| `stop` | запись 1: тормозить рампой, оставить удержание; чтение 1 означает команду остановки, не подтверждение неподвижности |
| `move` | скорость, микрошаг/с, со знаком |
| `move_rad` | скорость, рад/с, со знаком |
| `tmc_pos_set` | абсолютная целевая позиция, целые микрошаги int32 |
| `pos_set` | абсолютная целевая позиция, радианы |
| `pos_steps` | текущий XACTUAL, целые микрошаги, только чтение |
| `pos_get` | текущая расчётная позиция, радианы, только чтение |
| `velocity` | текущая расчётная скорость, рад/с, только чтение |
| `zero_set` | запись 1 обнуляет счётчик на неподвижном моторе; не калибровка |
| `gear_ratio` | передаточное отношение; менять только при `arm=0` и неподвижном моторе |
| `vel_set` | положительная скорость позиционного движения, рад/с |
| `acceleration` | положительное ускорение/торможение, рад/с² |
| `ihold`, `irun` | 0…31, изменяются на лету |
| `ihold_delay` | 0…15, изменяется на лету |
| `global_scaler` | 0 = полный масштаб, либо 32…255 |
| `command_timeout_ms` | таймаут скоростной команды; начально 3000 мс, 0 отключает, максимум 3600000 |
| `status` | `[armed, mode, last_error, uptime_ms, spi_error_count, last_hal_spi_status]` |
| `tmc_diag` | `[GSTAT, DRV_STATUS, IOIN, IHOLD_IRUN, GLOBAL_SCALER, RAMPMODE, RAMP_STAT, CHOPCONF, PWMCONF_config, GCONF]`, raw int32 |

`mode`: 0 остановка/удержание, 1 скорость, 2 позиция (остаётся 2 после достижения
цели). `last_error`: 0 принято, 1 неверный тип/диапазон, 2 мотор выключен,
3 требуется остановка/выключение, 4 ошибка SPI/идентификации TMC.
Неверная запись возвращает прежнее значение; причину читать в `status`.
NaN, infinity, дробные целые и переполнение XACTUAL отклоняются.
Ускорение и скорость проверяются на представимость в регистрах TMC.
`tmc_diag` — сырые значения: старший установленный бит даёт отрицательный int32.
Чтение GSTAT/RAMP_STAT может сбрасывать флаги событий, поэтому диагностическое
чтение не является пассивным снимком всех защёлок.

Скоростную команду нужно повторять чаще таймаута. По таймауту мотор тормозит
и остаётся включённым. Позиционное движение продолжается автономно до цели.
`arm 0` немедленно снимает удержание. Автоматического поиска упоров и автокалибровки нет.

## Yakut на Raspberry Pi

Для установленного Yakut (`y` — его короткая команда):

```sh
export UAVCAN__NODE__ID=100
export UAVCAN__CAN__IFACE=socketcan:can0
export UAVCAN__CAN__MTU=64
# Если драйвер подключён к другому порту — заменить can0 на can1.
y rl 42                # список регистров
y r 42 status
y r 42 tmc_diag
y r 42 irun 6
y r 42 ihold 2
y r 42 gear_ratio 19.203208
y r 42 vel_set 0.1
y r 42 acceleration 0.5
y r 42 arm 1
y r 42 move_rad 0.05    # остановится через 3 с без обновления команды
y r 42 stop 1
y r 42 velocity        # дождаться нуля перед zero_set
y r 42 zero_set 1
y r 42 pos_set 0.1
y r 42 tmc_pos_set 10000
y r 42 pos_steps
y r 42 stop 1
y r 42 arm 0
```

`can0` и `can1` на Pi уже настроены на 1/8 Мбит/с. Ни один из них ещё не
подтверждён как физическое подключение платы: до прошивки трафика не наблюдалось.

## Программа испытаний

1. Подставить обновлённый `.h`, пересобрать, проверить API и значения регистров.
2. После записи образа подтвердить Heartbeat/GetInfo, Register List/Access и
   IOIN; проверить IHOLD_IRUN readback при изменении каждого тока.
3. Без нагрузки проверить оба направления, скорость, позицию в микрошагax и
   радианах, редуктор, ноль, stop, arm/disarm и таймаут.
4. Для удержания: фиксировать IHOLD, IRUN, GLOBAL_SCALER, питание, температуру
   окружающей среды, время выдержки, температуру мотора/драйвера и момент
   начала проворота. Момент на выходе = сила × плечо перпендикулярного рычага;
   для подвешенной массы — m × g × L.
5. Для движения: при одинаковых скорости/ускорении и нагрузке увеличивать IRUN,
   записывать максимальный устойчивый момент, нагрев и наличие пропусков шагов.
   Удержание и движение измерять отдельно, для каждого режима выдерживать
   одинаковое время до стабилизации температуры.

Физическую температуру мотора и реальный момент эта прошивка не измеряет:
нужны внешний термометр и нагрузочное приспособление. DRV_STATUS доступен для
оценки состояния драйвера. Окончательные токи выбираются по этим измерениям;
значения 0…31 сами по себе не являются амперами и зависят от RSENSE и scaler.

## Обновление библиотеки

```sh
./scripts/sync_tmc5160.sh
cmake --build build
```

Скрипт копирует актуальный `.h` из SPI-проекта без изменений, записывает исходный
commit и SHA256 в `TMC5160_SOURCE.txt` и запускает host-тесты. `robot_config.h`
сохраняет настройки стенда. На момент синхронизации моторные настройки совпадают
с SPI-проектом; добавлены только параметры BENCH.

## Что проверено

Release-сборка и host-тесты преобразований/диапазонов. Дополнительно реальный
`tmc5160.h` проверен с имитацией HAL/SPI и включёнными AddressSanitizer/UBSan:
двухкадровое чтение с переключением CS, порядок байтов, отрицательные позиции и
24-битная скорость, запись токов, scaler, направления, ускорение, позиционирование,
stop, zero, arm/disarm и init. Это проверка программного API и формируемых
SPI-запросов; электрический обмен и реакция двигателя требуют проверки на плате. Записи Flash, движения,
проверки CAN/SPI на новом образе и измерений под нагрузкой пока не было.

## Проверка на стенде 2026-10-16

Образ с IHOLD=0/IRUN=0 записан через ST-Link, OpenOCD подтвердил Verify OK
и определил 128 КиБ Flash. После аппаратного reset MCU входит в системный
ROM (PC `0x1fff3b28`, VTOR `0x1fff0000`). Для проверки приложение запущено
через SWD установкой MSP/PC из векторов Flash и VTOR=`0x08000000`.
После этого на **can0** Raspberry Pi наблюдается CAN FD Heartbeat узла 42:
ID `107D552A`, период около 1 с, uptime растёт. Option Bytes не менялись;
автозапуск после reset/включения питания ещё требует исправления.

Автозапуск исправлен через Option Bytes: OPTR `0xffeff8aa` → `0xfbeff8aa`,
`nSWBOOT0=0`, `nBOOT0=1` (BOOT0 берётся из Option Bytes, загрузка основной Flash).
Остальные биты сохранены, включая RDP=0xAA. Запись маской `0x0c000000`.
Команда OpenOCD option_load вернула ошибку при перезапуске; повторное подключение
подтвердило новое OPTR. После обычного `reset run` PC находится во Flash
(`0x0800755e`), Heartbeat узла 42 снова наблюдается на can0 с растущим uptime.
Отключение и повторная подача питания отдельно не проверялись.


## Общая установка Yakut на Raspberry Pi

Установлены Yakut 0.13.0, PyCyphal 1.20.0, Nunavut 2.3.1 в отдельном
окружении `/opt/yakut/venv`. Общие команды `/usr/local/bin/y` и
`/usr/local/bin/yakut` доступны всем пользователям, включая SSH без login shell.
Прежние launchers в `/home/pi/.local/bin` сохранены с суффиксом
`.before-system-install`, вместо них ссылки на общую команду.

Стандартные пространства **uavcan и reg** скомпилированы в `/opt/yakut/dsdl`
из public_regulated_data_types, commit
`86e2f332419ff015f4cc9f1bb7843b02d5f7a5ed`. Исходники доступны в
`/opt/yakut/public_regulated_data_types`; полный список установленных Python
зависимостей сохранён в `/opt/yakut/requirements.lock`. Каталоги принадлежат
root, доступны всем для чтения. Для Python внутри общего venv добавлен `.pth`
с каталогом скомпилированных DSDL.

Общий launcher и `/etc/profile.d/yakut.sh` задают значения по умолчанию:

```sh
YAKUT_PATH=/opt/yakut/dsdl
UAVCAN__NODE__ID=100
UAVCAN__CAN__IFACE=socketcan:can0
UAVCAN__CAN__MTU=64
```

Любое значение можно переопределить через окружение. Для другого CAN-порта:
`UAVCAN__CAN__IFACE=socketcan:can1 y r 42 status`.

Проверено от `pi` и от `nobody` с пустым окружением: Register Access работает
без sudo. `y rl 42` вернул 20 регистров; `y r 42 ihold` и `y r 42 irun` вернули 0;
`status` показал `[0,0,0,uptime,0,0]`. Мотор при проверке не включался.
Скрипт `scripts/setup_yakut_system.sh` повторяет компиляцию и настройку общих
команд при уже установленных venv и исходниках DSDL.


## Кнопки VS Code

Открыть каталог `bustepper` в VS Code через WSL. Установлено расширение
`groobz.command-buttons`; конфигурация — `.vscode/command-buttons.json`.
В нижней строке доступны:

- **Build** — настроить CMake/Ninja и собрать Release в `build`.
- **Flash ST-Link** — прошить уже собранный `build/bustepper.elf`, проверить
  запись и перезапустить MCU.
- **Build + Flash** — последовательно собрать и прошить; при ошибке сборки
  прошивка не запускается.

`Ctrl+Shift+B` запускает сборку. При отсутствии кнопок выполнить
`Developer: Reload Window` либо `Command Buttons: Reload` из палитры команд.


Частота StealthChop: `ROBOT_TMC_PWM_FREQ=3`, `PWMCONF=0xC40F001E`.
При TMC clock 12 МГц это ~29.27 кГц на каждом силовом выходе; эффективная
частота chopper в терминологии datasheet ~58.54 кГц. PWMCONF доступен только
для записи: элемент PWMCONF_config в tmc_diag — отправленная конфигурация
из прошивки, а не аппаратный readback. Остальные поля PWMCONF сохранены
на reset defaults, включая autoscale/autograd. Частота SpreadCycle этим полем
не задаётся; переход режимов по TPWMTHRS остался без изменений.


## Подключённый UI и телеметрия Cyphal

В прошивку добавлена публикация `reg.udral.physics.kinematics.rotation.Planar.0.1`
на subject **1042**, каждые **50 мс**, как feedback в РУКЕ. Позиция и скорость
в радианах/рад/с выходного вала получаются из TMC5160. Для UI не опрашиваются
регистры pos_get/velocity. Управляющие команды и настройки по-прежнему идут
только через `uavcan.register.Access`.

Развёртывание UI на Pi: `./scripts/deploy_ui.sh`.
Подробности — `ui/README.md`. Адрес **http://192.168.1.104:8088**. Мост на Pi использует
node-ID 101, can0 CAN FD MTU 64, целевой узел 42. Yakut на node-ID 100 продолжает
работать независимо. Сервис на Pi отдаёт UI по HTTP и передаёт телеметрию/команды через WebSocket
на порту 8088. Для работы не требуются WSL или SSH-туннель.

Прошивка с feedback записана через SWD, Verify OK. Никакие команды включения
или движения при этой проверке не отправлялись. В момент обновления Raspberry
Pi выключен/недоступен по SSH: физическая проверка подписки CAN и движения
с UI отложена до включения стенда. Связной процесс повторяет подключение и
установит/запустит CAN-мост при восстановлении SSH.

Проверки без оборудования:

- Сборка firmware и `scripts/test.sh`.
- `tests/bridge-integration.py` с реальными PyCyphal/DSDL через loopback UDP:
  публикация/подписка, Register Access, отсутствие записей при старте,
  запрет запоздавших команд, ошибки привода, устаревание телеметрии.
- `tests/ui-live.cjs`: браузер с полностью перехваченным API; кнопки команд,
  скоростной keepalive, обе кнопки Stop, получение позиции из телеметрии,
  отсутствие движения после реконнекта, мобильная компоновка.


Панель перенесена целиком на Raspberry Pi: `bustepper-can.service` обслуживает
HTTP + WebSocket непосредственно на 8088. Автозапуск включён, HTTP и реальные
отсчёты Cyphal в браузере проверены. Старый локальный сервер и SSH-туннель
остановлены, их исходники удалены. SSH нужен только скрипту обновления.
