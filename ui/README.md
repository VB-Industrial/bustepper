# BUStepper — панель на Raspberry Pi

Открыть **http://192.168.1.104:8088** с компьютера/телефона в сети стенда.
WSL, локальный сервер и SSH-туннель для работы панели не нужны.

На Raspberry Pi работает системный сервис `bustepper-can.service` от пользователя
pi. Один aiohttp-процесс отдаёт UI по HTTP и обслуживает `/ws` на порту 8088.
Он запускается при загрузке Pi и перезапускается при сбое.

- Статика: `/home/pi/bustepper/ui`.
- Сервер: `/home/pi/bustepper/can_bridge.py`.
- Python: `/opt/yakut/venv/bin/python`, зависимости в `server/requirements.txt`.
- DSDL: общий `/opt/yakut/dsdl`.
- Серверный Cyphal node-ID: **101**, can0 CAN FD MTU 64. Yakut остаётся на 100.

Прошивка узла **42** публикует `reg.udral.physics.kinematics.rotation.Planar.0.1`
на subject **1042**, 20 Гц. Позиция и скорость рассчитаны TMC5160, относятся к
выходу редуктора; внешнего энкодера нет. Сервер принимает только источник 42
и передаёт отсчёты браузеру по WebSocket. Скорость двигателя в об/мин вычисляется
через редуктор. Три графика показывают 20 секунд истории, симуляции нет.

Все команды и настройки идут через Cyphal Register Access. Настройки читаются
раз в секунду, status/XACTUAL — дважды в секунду. Позиция/скорость приходят
подпиской, без RPC-опроса. WebSocket-команда получает подтверждение или ошибку
после ответа привода. При открытии страницы записи в CAN не выполняются.

Скоростная команда повторяется каждые 500 мс только после нажатия направления.
Стоп/выключение/переход к позиции прекращают обновление скорости. При скрытии
вкладки/закрытии страницы отправляется stop и прекращаются обновления;
независимо от доставки stop прошивка тормозит скоростной режим через 3 с без
команд. Позиционное движение автономно продолжается до цели.

Без свежей телеметрии (>500 мс) команды движения блокируются, значения `—`.
Реконнект не возобновляет движение. При выключенном питании TMC CAN может
оставаться доступным от SWD — это не подтверждает наличие силового питания.

## Обновление

Из рабочего каталога разработчика:

```sh
./scripts/deploy_ui.sh
```

SSH используется только для административной установки/обновления; после
развёртывания браузер обращается напрямую к Pi. Поддерживается SSH key/agent
либо SSHPASS в окружении, пароль в файлах проекта не хранится.

На Pi: `systemctl status bustepper-can`,
`journalctl -u bustepper-can -f`, `sudo systemctl restart bustepper-can`.

## Проверки

`tests/bridge-integration.py`: реальные PyCyphal/DSDL через loopback UDP,
Register RPC и WebSocket, ошибки прошивки, устаревание и запрет cross-origin.
`tests/ui-live.cjs`: API полностью подменён WebSocket-обработчиком Playwright,
никаких аппаратных команд; проверены keepalive, обе кнопки stop, настройка тока,
отсутствие записей при загрузке и после реконнекта, мобильная компоновка.
Реальная страница Pi проверена в браузере: 20 Гц feedback, нет JS-ошибок,
при открытии/закрытии не отправлены команды приводу.

Скорость позиционного перемещения задаётся регистром `vel_set` (рад/с выхода),
поле находится на вкладке «Позиция». Это VMAX рампы, разгон/торможение задаёт
`acceleration`. Старое имя `position_speed` удалено.
